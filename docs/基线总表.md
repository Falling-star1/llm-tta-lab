**用途**：这是后续研究引用的唯一基线表。所有数字来自服务器 `run_manifest.json` / `metrics.json`，配置见 §3，已知偏差见 §4。
**使用规则**：
- 只引用本表的数字，不要从别处摘；同一格在别处出现不同数值时以本表为准。
- 每个方法只用 §3 冻结的那一套配置。**不允许为对齐论文再调参**——调过的配置不是基线。
- `quality` 列标记该格的输出是否塌缩。标 `COLLAPSED` 的格子数字仍如实保留，引用时必须同时说明。

## 4. 已知复现缺口（不再调参追平）

**1. Tent 的 geo / dolly 方向相反，单一 lr 无解。**
Dolly 我们太狠（−0.2985 vs 论文 −0.1273），GeoSignal 我们太轻（−0.0047 vs 论文 −0.0570）。论文 Appendix C.2 只公开「Tent/EATA 都用模型自生成 80 token 的预测熵」和「EATA 的 E0 = 0.4」，**适配面、lr、初始化均未公开**；官方仓库全仓 grep `tent|eata|come` 零命中，无法核对。三组 lr 试点（`--sched const/cosine` × `1.5625e-5/5e-6`）证明降 lr 只会让 dolly 接近、geo 更偏离。记录见 #17。

**2. EATA 的 GSM8K 未复现出论文的塌缩。**
论文 0.0032（Δ −0.7724），我们 0.7784（Δ +0.0024）。该组用 `d_margin=1.0`，与静默冻结的 `lora_llama3b_dolly`（0.0910，4067/5000 batch 被筛空）同口径；`lora2_*` 用 `--d-margin 0`，geo/dolly 都塌得与论文吻合。**假设：GSM8K 改用 `--d-margin 0` 会塌到 0.003 量级，未验证。**

**3. TLM 的 GSM8K 差 0.13，是全表最大缺口。**
论文 +0.1340，我们 +0.0038。适应量差约 500 倍：GSM8K 选中率 51%、加权总损失 574、峰值 lr 1e-6；Geography 选中率 85%、总损失 5973、lr 5e-5。论文写死 lr 1e-6、官方 yaml `num_train_epochs: 1.0` 均已核对，非我们配置错。

另外两处需要说明但不是缺口：
- **DeYO / SAR 没有论文数字可对齐**（TLM 论文基线只有 Tent / EATA / COME），它们的参照系是同适配面的 Tent。
- **`E0 = 0.4·lnV` 在文本任务上筛不掉样本**：实测逐 token 熵 0.16~1.5 nats，而 `E0 = 4.70`。所以 EATA 与 SAR 实际都是「全样本更新」。这是与论文同条件的结果，不是 bug；若要筛选真正起作用需按分位数标定（DeYO 已这么做，见 §3）。

## 5. 产物路径

服务器结果根目录 `/data/chuwenjing/results/`，2026-11-18 重组后：五个方法各占一个目录（只放全量正式结果），其余实验按性质归入分类目录。

```
results/
├── source/       <模型>__<数据集>/source.jsonl  6 份规范 Source（其余位置为硬链接）
├── tent/         <模型>__<数据集>/            6 格
├── eata/         lora2_*/ lora_*/             6 格有效 + 1 格旧口径
├── tlm/          <模型>__<数据集>/            6 格（qwen/dolly 为补救组）
├── deyo/         deyo_gamma_<模型>__<数据集>/  6 格
├── sar/          sar_gamma_<模型>__<数据集>/   6 格
├── sensitivity/  sar_r0.02_*                  6 格（SAR reset 比例敏感性）
├── diagnostics/  各类诊断、冒烟、TLM pilot、v7 content
├── preflights/   各类预检
├── archives/     Tent-LoRA v3 六组（已作废，保留对照）
└── _archive/     eata_text 整族日志
```

每个方法目录下另有 `logs/`；`tlm/run_records/` 存 run 级 JSON。

**Source 的存法**：Source 不是一次独立实验，而是每格适应前的评测，所以它随方法一起产出（`source.jsonl` + `run_manifest.json` 的 `source` 段）。全站只有 6 种不同内容（一个模型×数据集一格），统一放在 `source/`；`tent/`、`eata/`、`deyo/`、`sar/`、`sensitivity/`、`archives/` 里的副本都是指向它的**硬链接**（同一 inode，不占额外空间）。TLM 不用副本，而是 `source_reuse.json` 记录源路径与 sha256。

六份 Source 的原始产出是 2026-10-20 那次 Tent-LoRA v3 跑的 Source pass（`archives/tent_lora_b1_v3_20261020_001210/…`），之后所有方法都用 `--reuse-source` 复用，sha256 完全一致。

**硬链接的注意点**：这些文件现在是同一 inode，就地修改一处会同时改变所有位置。它们是只读记录，正常流程不会写；若要改动请先 `cp` 成新文件。

**兼容软链接**：重组后旧路径仍然可解析，历史 JSON 与文档里的绝对路径不需要改写。`tent_paper/`、`eata_lora`、`tlm_offline_v6_ready/`、`tlm_qwen_dolly_recovery_v6/`、`tlm_offline_v7_content`、`sar_deyo/` 均为指向新位置的软链接（部分保留了原来的嵌套层级）。另有 6 个更早的软链接（`source_smoke`、`tent_formal_v3_6gpu`、`tent_full_preflight*`、`tlm_dolly_followup`、`tlm_offline_v6_preflight`）保持不动。
