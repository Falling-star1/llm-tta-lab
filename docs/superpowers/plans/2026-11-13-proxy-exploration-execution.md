# 代理方向探索实验实施计划

用户已授权执行三阶段设计。内联执行，遵守单写入任务规则。仅提交本工作树的 experiments/proxy_exploration_v1、相关测试、协议及交接。

1. 读当前任务 Issue #14、历史试点 #13 和服务器站点配置、已存在运行状态，防止重复执行。
2. 在加载其余五组得分前冻结两模型、三数据集范围以及每数据集共同的五段 ID，Dolly 沿用已有 ID。将规则、池大小 64、子空间维度 5、seed 42 和全部指标写入新协议。
3. 对六组的完整源文件清单和来源做核对，读取输入、Source、底模 CE 和 token 元数据的字段、哈希和行数。Source 与 TLM 成绩区分。
4. 先写统计核心测试，验证共同 ID、四分位、指标类型和配对/非配对区间规则；运行失败后实现最小逻辑。256 题四档各 64，统一给六组输出原始分布和区间。
5. 以源文件/代码指纹、新 protocol_id、完整 commit 和 CPU 预算创建请求，labctl plan 通过后服务器独立会话 run，收集并独立复算六组结果。
6. GPU 阶段固定覆盖全部六组，最多六卡并行，每组合一张卡。同一组合按依赖顺序执行。复用冻结运行时的输入 CE、模型加载、生成和评分。梯度池为低 CE 64 条和随机 64 条，无标签。采集时记录 LoRA 零 A 梯度和有效秩。
   在独立 diagnostic 256 题中固定最低/最高各 64 题，GSM8K 按 EM、Dolly/GeoSignal 按隐藏 CE/模型/梯度的盲评划分回答好/差。先冻结标签再关联梯度。比较低 CE 好/差为主、高 CE 好/差为补充；计数、未决、等量抽样 ID、余弦、谱和历史池 U 的保留率均报告。四个文本组合合计 512 条诊断回答待评，复用已有梯度而不新增训练组。
7. 先以小张量验证 SVD、投影、优化器参数位移与幅度匹配，然后固定 GPU 入口、请求和预算。通过短真实预检后执行实验二。
8. 实验三使用同一初值、500 条适应流及 300 条独立评测，修订为 Source/普通 A+B/普通 B-only/随机池/低池/B-only 同步长六条件。固定优化器和投影对象，报告实际写回位移与 A 位移。恢复包含参数、优化器、随机数、游标及冻结索引；每个阶段检查点原子写入。输出逐题配对差和资源记录。更新协议为 proxy-e3-six-adam-step-v3，预检为 proxy-six-preflight-v3。六组修订预算为 15,000 次访问和 9,000 次生成，须在正式请求及执行授权中明确。
9. 回填 Issue 的执行与质量状态、commit、命令、输出和未完成项目。历史错误通过新协议与说明修订，旧原始文件不覆盖。

验证项目以实验身份、分割互斥、已知分数的独立重聚合、有限性及投影残差为主。各阶段通过所需检查后继续，GPU 训练不用于替代单元测试。
